## 0. 调研结论摘要（本文档的地基）

### 0.1 DSH web UI 视觉语言（本机实装核实，非推测）

来源：`~/.npm/_npx/.../node_modules/@deepseek-ai/dsh-client-ui-theme`（v0.1.0-rc.6，官方 NPM SDK）+ 社区参照插件 `dsh-web-ui/packages/dsh-task-board`（本机 `~/.dsh/profiles/web`）。

**官方设计平台是三层 token 体系**（这是本项目最重要的设计事实）：

```
--dsw-static-*     primitive 色板（light/dark 两套，值不随主题变）
       ↓
--dsw-alias-*      语义别名（bg-layer / label-primary / border-l2 / button-info-fill / state-error-primary…）
       ↓            light 默认挂在 body；dark 挂 body[data-ds-dark-theme]
--dsw-specific-*   组件特化（sidebar-fill / sidebar-nav-item-active / bubble / input-major…）
```

核实到的关键值（light 主题）：

| 语义 | 指向 | 解析值 |
|---|---|---|
| 页面基底 `bg-base` | neutral-bluish-00 | `#FFFFFF` |
| 侧栏底 `sidebar-fill` | neutral-bluish-50 | `#F9FAFB`（冷灰，带 bluish 色调） |
| 边框分层 `border-l1..l4` | 黑 alpha | `rgba(0,0,0,.04 / .10 / .12 / .16)` |
| 正文 `label-primary` | neutral-bluish-1000 | `#0F1115` |
| 次级/三级文字 | neutral-bluish-700 / 600 | `#61666B` / `#81858C` |
| 品牌蓝（info 按钮、业务状态） | deepseek-500 | `rgb(65,118,230)` = **`#4176E6` 纯色平涂** |
| 品牌蓝 hover | deepseek-400 | `#679EFE` |
| 主按钮（宿主默认） | neutral-bluish-1000 | 近黑 `#0F1115`（非蓝） |
| 语义色 | state-success/warn/error | `#22C55E` / `#F59E0B` / `#EC1313` |

- **字体**：`--dsw-font-family` = `-apple-system, BlinkMacSystemFont, 'Segoe UI', 'PingFang SC', 'Hiragino Sans GB', 'Microsoft YaHei', …`（系统栈，零网络字体）；代码 `--ds-font-family-code` = `'SF Mono', 'JetBrains Mono', 'Fira Code', …`（官方注释明确：不带裸 `monospace` 尾巴，防 Windows CJK 回落宋体）。
- **动效**：`--ds-transition-duration-fast/base/slow` = 0.1s / 0.2s / 0.3s，缓动 `cubic-bezier(0.4,0,0.2,1)`。
- **字重**：Figma 510 一律渲染为 CSS 500（官方注释）。即项目可用字重 = 400 / 500 / 700，无中间值。
- **图标**：官方 primitives 自带 ~50 个 `IconXxxOutline14/16/20` 描边图标，风格 = 细描边、无填充、圆角端点。

**插件 UI 挂载机制**（task-board 实测模式，rc.6 现状）：

- 中心栏单占：第三方 UI 在 `[data-pane="conversation"]` 里 append 容器接管中心栏，`data-*` 属性控可见性；sidebar 无对外 slot，入口行靠 DOM 插入 + 自愈重插；跨面板互斥走 `dsh-panel-activate` CustomEvent。
- 插件设置可走官方 `settings.plugin.item` slot 挂卡片（有正式 slot）。
- 社区最佳实践（task-board 的 CSS 注释原话）："colors ride the dsh `--dsw-*` tokens so the board follows the active theme (light/dark and skins)"——**插件 CSS 全部挂宿主 token，浅色/深色/皮肤自动跟随，零适配成本**。

### 0.2 doocs/md 编辑器布局模式（仓库核实）

`apps/web/src` 结构：主视图 `CodemirrorEditor.vue` = **左 CodeMirror 6 Markdown 编辑 / 右 PreviewPanel 微信样式实时预览**双栏，顶部 `editor-header` 工具栏（格式化/主题模板/上传图片/**复制富文本**），右侧 `RightSlider` 抽屉（CSS 自定义/公众号账号配置/AI 工具箱），底部 Footer 状态栏；对话框族 = 模板选择 / 图片上传 / 公众号账号配置 / 导入 MD / 版本 diff。核心交付动作是「复制富文本 → 公众号后台粘贴」。

**对本项目的转译**：编辑+预览双栏、顶部动作条、右滑配置抽屉、状态栏——这套空间语法用户已被教育过，直接继承；但「复制粘贴」交付升级为「推草稿箱 API + 定时发布」（我们的产品化优势）。

### 0.3 React 生态假设——已本地升级为事实

任务书要求按 React 生态假设做设计并标注。**本地核实**：`@deepseek-ai/dsh-client-web-react` peerDeps = `react ^18.2.0`，官方 shell 侧提供 `createSlotRenderer / SessionProvider / useInvoke` React 胶水；社区 task-board 同为 React 18。React 18 假设成立且是平台事实（架构师侧的正式核实结论以架构文档为准，如有出入本文的组件结论不受影响——因为首选方案不依赖第三方 React 组件库，见 §5）。

## 1. 设计原则

### 1.1 寄存器与三轴刻度

- **Product 寄存器**（工具 UI，设计服务产品）：标杆是「赢得熟悉感」——像 DSH 宿主的亲生长出的一部分，而不是嵌进来的第三方页面。对标：Linear（密度与克制）、Stripe Docs（层级与排版）、doocs/md（空间语法）。
- 三轴刻度：`DESIGN_VARIANCE=3`（工具型可预测布局，非对称手法不进场）/ `MOTION_INTENSITY=3`（跟随宿主 100–300ms 功能动效，无装饰动画）/ `VISUAL_DENSITY=6`（内容创作工具，列表+编辑器中高密度，但不做驾驶舱）。

### 1.2 设计原则（6 条）

1. **宿主同源（Host-native）**：一切颜色/字体/动效经 `--ww-*` 语义 token 间接引用宿主 `--dsw-*` token。插件在浅色 DSH 里是浅色，在深色/换肤 DSH 里自动跟随。**不自带主题切换开关**（宿主已有，重复 = 冲突源）。
2. **克重平涂（Stripe 式）**：主操作色 = 品牌蓝纯色平涂；层级靠灰阶明度递进 + 1px 边框，不靠阴影堆叠；无渐变、无发光、无毛玻璃。
3. **工程编辑风（code-editorial）**：等宽字体用于一切「机器味」信息（slug、模型名、时间戳、门禁规则 ID、cron 表达式）；细描边图标；卡片圆角克制（8px 上限为主）；线框分层优先于阴影。
4. **中文是第一公民**：界面全中文真实产品文案，不用英文占位；中文排版按 16px 正文 / 1.7 行高 / 每行 ≤ 34 字设计。
5. **状态即界面**：写作管线是长时异步流程，生成中/门禁失败/排队/供应商 fallback 每个状态都有专属设计（§4），不做一个 spinner 打天下。
6. **安全默认可见**：「只到草稿箱、群发需显式 opt-in」是产品价值观，必须长在 UI 结构里（发布动作永远先落草稿箱，freepublish 入口默认隐藏 + 双确认），不是埋在文档里的注意事项。

### 1.3 Jerry 审美偏好转译

| Jerry 偏好 | 设计转译 |
|---|---|
| 浅色底深色内容 | 不做插件自有暗色模式；light 主题 = 白底 `bg-base` + 近黑正文 `label-primary`（宿主 light 即此结构，天然满足） |
| 蓝色纯色平涂、不要渐变 | 主操作蓝 = 宿主 deepseek-500 `#4176E6` 纯色；token 层零渐变定义（§6.2 由构造保证） |
| 图标克制 | 全项目锁 lucide-react 一套（§7），细描边、16/20px 两种尺寸走天下，无彩色图标无填充图标 |
| 工程编辑风 | 等宽字体信息带、`border-l2` 分层、8px 圆角、状态点（StateDot）语言 |
| 反 AI 模板味 | §8 十三项自查清单逐条对照 + 空状态/文案用真实示例（§3 各页空状态） |

### 1.4 P0 三条由构造保证（设计侧手段）

| P0 门禁 | 构造保证手段 |
|---|---|
| ① 禁 emoji 作功能图标 | Spec 锁 lucide-react 为**唯一**图标库；组件层只暴露 `<Icon name>` 封装，业务代码不直接写 SVG；CI 扫人格文件的 emoji 正则 `[\x{1F300}-\x{1F9FF}\x{2600}-\x{26FF}\x{2700}-\x{27BF}]`（白名单：仅 UGC 正文） |
| ② 禁紫→粉渐变主视觉 | token 层**不定义任何 gradient token**——`--ww-*` 全部是纯色/边框/阴影引用；加 stylelint 规则 `declaration-property-value-disallowed-list: linear-gradient`（除微信预览画布内的文章内容样式——那是 UGC 排版主题，非 UI chrome，且微信主题本身也不含紫粉渐变）；紫粉四色值不出现在任何 token |
| ③ 禁 AI 模板味 | ①空状态全部用真实中文产品文案（本文 §3 已写死示例，前端不得改写成「欢迎使用」）；②示例数据用有机真实值（如「阅读 4,721」而非「10,000+」）；③无营销 Hero——这是工具界面，首屏 = 工作内容本身；④颜色全部经 token 引用，组件内零裸 hex（`#fff`/`#000` 亦用 token） |

## 2. 信息架构

### 2.1 空间容器

插件 UI = DSH 中心栏内的一个「面板应用」（task-board 模式：接管 `[data-pane="conversation"]`，sidebar 插入入口行）。面板内部结构：

```
DSH 宿主外壳（sidebar / composer，宿主资产，不动）
└── [中心栏] dsh-wewrite 面板
    ├── 面板顶栏（二级导航 Tab ×5 + 右侧：公众号连接状态 · 版本号）
    └── 内容区（按 Tab 切换 5 个页面）
```

### 2.2 导航结构（5 个顶级 Tab，认知负荷 ≤5）

```
写作台 ── 选题中心 ── 文章库 ── 定时任务 ── 设置
(Dashboard)  (Hotspots)  (Articles)  (Schedule)  (Settings)
```

顺序 = 使用频率动线：**选题 → 写 → 排期** 是主回路，写作台是回路起点，设置一次性配好后少动。

对任务书建议的优化说明：保留 5 区结构；「文章库+编辑器」拆为「文章库列表页 + 点入编辑器视图」（编辑器是列表的下钻态，不占顶级 Tab，编辑器内有显式返回）；「设置」独立成 Tab 而非全并入宿主 settings slot——因为配置面大（公众号/LLM/图片供应商/代理四组），宿主 settings.plugin.item 卡片只挂「插件总开关 + 打开完整设置」的入口卡（rc.6 第三方 settings namespace 有 allowlist 缺口，卡片兜底显示说明文案，见 task-board 先例）。

### 2.3 页面-路由草案（面板内状态路由）

```
/                 写作台
/hotspots         选题中心（热门榜）
/articles         文章库（列表）
/articles/:id     编辑器（列表下钻，含预览）
/schedule         定时任务（队列 + 历史）
/settings         设置（公众号 · 模型 · 图片 · 代理 · 发布纪律）
```

### 4.2 生成中（长时异步态，核心状态设计）

- 六阶段 stepper（选题→研究→写作→门禁→排版→配图），完成项折叠为单行结果摘要，当前项展开子状态。
- `转入后台`：生成期间可切去文章库/设置，写作台待办区显示 `◐ 正在生成…` 行，完成后系统通知（宿主 Toast + 面板内红点）。

### 4.3 门禁失败（质量是产品灵魂，给足设计权重）

```
┌────────────────────────────────────────────────────┐
│ 门禁报告  68/100  ▪shield-alert 3 项未过            │
│ ┌────────────────────────────────────────────────┐ │
│ │ ▪alert 人味不足   humanness 41（阈值 55）              │ │
│ │   L42–L58 连续 3 段无具体数字/专名               │ │

│ │ ▪alert 编号配图不一致   文中「图 3」缺对应图片           │ │
│ │   [查看配图位]                                   │ │

│ └────────────────────────────────────────────────┘ │
│ [AI 修这稿（全部）]  = 重新生成仅修复问题段落          │
└────────────────────────────────────────────────────┘
```

- 每条失败规则：规则中文名 + 内部 ID（等宽小字）+ 具体定位（行号/段落）+ 单项修复动作。
- `AI 修这稿` 只重写问题段落，保留已通过部分（尊重编辑过的内容，diff 视图展示改动）。

### 4.4 预览（微信样式）

- 375px 固定宽白画布，内容 = `md2html.mjs + inline_styles.mjs` 的**真实产物**（与推到草稿箱的字节一致——所见即所得的定义是「与 API 载荷一致」）。
- 画布顶部模拟公众号文章头（账号名/日期），帮助建立心理预期；画布属 UGC 内容区，排版主题 CSS 与 UI chrome 隔离（作用域限定在画布容器内）。
- `手机实机预览`：生成临时 URL + 二维码，手机扫码看真实移动端渲染。
- 排版主题切换（继承 doocs/md 的多主题能力）：画布右上 `主题 ▾`，主题属于文章资产随文章保存。

### 4.5 推草稿箱与排队发布

- 主按钮 `推草稿箱`：立即调用 draft/add，按钮态 = `推送中…` → 成功 Toast「已进草稿箱」+ 列表状态变 `● 草稿箱`；失败 Toast 显示具体原因（IP 白名单 / token 过期）+ `[去设置代理]` 直达。
- `定时…` 弹层：时间选择 + 重复规则（一次/每天/每周几，翻译成 RRULE 等宽原文展示）+ 目标 = 草稿箱（默认锁定）。
- 排队态生命周期：`○ 已排期 → ◐ 时间到·执行中 → ● 已进草稿箱`；执行失败 → `▲ 失败·已重试 1/3`，3 次后停队列 + 写作台待办红点提醒，不静默丢弃。
- 时间到但文章仍处「门禁未过」：**任务拦停**（不推不合格稿），生成一条待办 `定时到达但门禁未过，已拦停`——安全默认在流程层的落点。

## 5. 组件库选型（为「中文内容创作工具」）

### 5.1 决策框架

选型第一约束不是「哪个库好看」，而是**插件形态的四条硬约束**（来自 FACTS + §0 调研）：

1. 主题必须跟随宿主 `--dsw-*` token（浅/深/皮肤三态自动切换）；
2. no-build 安装路径优先（降低开源信任门槛）；
3. 体积与依赖面最小化（寄生在宿主页面里，不能拖累宿主首屏）；
4. 视觉不能与宿主打架（否则「嵌进来的第三方页面」感 = 反 Product 寄存器原则）。

### 5.2 候选评估（React 生态假设下）

| 候选 | 主题跟随 `--dsw-*` | no-build 友好 | 视觉一致性 | 评估 |
|---|---|---|---|---|
| **A. 官方 primitives 为主 + 定制补充**（推荐） | 原生（就是宿主组件） | peerDep 零打包 | 完全同源 | Button/Input/Menu/Modal/Toast/Tooltip/Pill/StateDot/DisclosureRow/RiskConfirmation/MarkdownText/CodeBlock 已覆盖本项目 80% 原子需求 |
| B. shadcn+Radix（次选，仅补缺） | 需改造为 CSS 变量映射（shadcn 本就 CSS vars 体系，改造浅） | 代码拷入 | 需全量重皮 | 只在需要复杂无头交互（如可访问日期选择）且官方 primitives 缺位时**按需拷入单个组件**并重映射到 `--ww-*` |
| C. Arco Design | 自带粒子变量体系，双 token 体系并存 | 需构建 | 字节设计语言 | 落选：视觉冲突 + 维护两套主题 |
| D. Ant Design v5 | CSS-in-JS 运行时 + 自带设计语言 | 需构建 | 后台脸（AI 模板味高危项） | 落选：运行时开销、包体、`#1677ff` 蓝与宿主蓝打架 |

**结论**：`官方 @deepseek-ai/dsh-client-ui-primitives 为基座 + 缺什么补什么`（优先自己写挂 token 的轻组件，其次按需拷 shadcn/Radix 单件重皮）；**不整库引入任何第三方组件框架**。理由：本项目是「中文内容创作工具」里最特殊的一类——**寄生型插件 UI**，宿主一致性权重远大于组件丰富度；而创作工具特有的重交互件（CodeMirror 6 编辑器、375px 预览画布）任何组件库都不提供，本来就要自建。
编辑器选型：**CodeMirror 6**（doocs/md 同款，MIT，无可争议）。

### 5.3 给架构师的交接点

- 依赖：`@deepseek-ai/dsh-client-ui-primitives`（peer）+ `lucide-react` + `@uiw/react-codemirror`（CodeMirror 6 React 封装）——三者均 ESM 可 no-build。
- 此选型对「React 生态假设」的敏感度低：即使架构师核实出非 React 栈（可能性低，已见 react peerDep），原则「官方 primitives 优先 + token 挂宿主」依然成立，仅 shadcn 补充件需换等价物。

## 6. 设计方向 Token 草案（Phase 2 输入，色值具体）

### 6.1 命名与分层策略

插件自有语义层 `--ww-*`（wewrite），**默认值全部指向宿主 token**；宿主 token 缺位处（圆角/间距）用自有 primitive。这样 Phase 2 的 design-tokens.json 每项都有「自有语义名 → 宿主引用 → 解析值（light/dark）」三列，浅深主题零媒体查询。

### 6.2 色板（蓝纯色主色 + 中性灰阶，无渐变）

```
--ww-accent            → var(--dsw-alias-button-info-fill)      /* light #4176E6 / dark #679EFE */
--ww-accent-hover      → var(--dsw-alias-button-info-hover)     /* light #679EFE / dark #4176E6 */
--ww-accent-active     → var(--dsw-static-deepseek-600)         /* #4868B2 */
--ww-accent-on         → #FFFFFF（token 化为 --ww-accent-on，不裸写）
--ww-accent-subtle     → var(--dsw-static-deepseek-50)          /* #EDF3FE，选中态底/焦点环底 */
--ww-accent-ring       → rgba(65,118,230,.32)                   /* focus ring，accent 32% 透明 */

--ww-bg                → var(--dsw-alias-bg-base)               /* light #FFFFFF / dark #151517 */
--ww-surface           → var(--dsw-alias-bg-layer-2)            /* light #FFFFFF / dark #2C2C2E */
--ww-surface-sunken    → var(--dsw-specific-sidebar-fill)       /* light #F9FAFB / dark #1B1B1C，嵌套区/预览画布外圈 */
--ww-fg                → var(--dsw-alias-label-primary)         /* light #0F1115 / dark #F9FAFB */
--ww-fg-secondary      → var(--dsw-alias-label-secondary)       /* light #61666B / dark #CFD3D6 */
--ww-fg-tertiary       → var(--dsw-alias-label-tertiary)        /* light #81858C / dark #81858C */
--ww-border            → var(--dsw-alias-border-l2)             /* rgba(0,0,0,.10) / rgba(255,255,255,.12) */
--ww-border-strong     → var(--dsw-alias-border-l3)
--ww-divider           → var(--dsw-alias-border-l1)

--ww-success           → var(--dsw-alias-state-success-primary) /* #22C55E */
--ww-warn              → var(--dsw-alias-state-warn-primary)    /* #F59E0B */
--ww-danger            → var(--dsw-alias-state-error-primary)   /* #EC1313 */
--ww-info              → var(--dsw-alias-state-business-primary)/* #4176E6，与 accent 同源 */

/* 微信预览画布（UGC 内容区，固定浅色——微信文章永远是浅底） */
--ww-canvas-bg         → #FFFFFF（固定值，不随主题，画布内是文章排版主题的域）
--ww-canvas-frame      → var(--dsw-alias-border-l2)
```

- **每屏 accent ≤ 2 处可见**：主 CTA（「开始写作」「推草稿箱」）+ 单一选中态。热榜「写这个」为次要按钮（ghost），不抢主路径。
- 纯黑 `#000`/纯灰 `#808080` 禁用；所有色已带 bluish 色调或品牌色调。
- **无任何 gradient token**（由构造满足 P0-2）。

### 6.3 字体

```
--ww-font-ui      → var(--dsw-font-family)         /* -apple-system…PingFang SC…Microsoft YaHei */
--ww-font-code    → var(--ds-font-family-code)     /* SF Mono / JetBrains Mono / Fira Code… */
--ww-font-canvas  → -apple-system…PingFang SC（画布内文章字体由排版主题控制，默认系统栈）
```

零网络字体（本地工具 + 性能 + DSH 同款栈）。JetBrains Mono 在已装用户机器上生效，未装回落 SF Mono/Consolas——与宿主行为完全一致。

字号（8 级）：`12 / 13 / 14(正文基准) / 16 / 18 / 20 / 24 / 32`；行高：正文 1.7（中文阅读），UI 文本 1.5，标题 1.3；字重：400 / 500 / 700（宿主 510→500 约束，不用 510/590 幻想值）；字距：中文正文 0，全大写拉丁标签 ≥0.06em，≥24px 标题 -0.01em。

### 6.4 间距 / 圆角 / 阴影 / 动效

```
间距：4px 网格   4 / 8 / 12 / 16 / 20 / 24 / 32 / 48（编辑器内边距 20，列表行高 44 触摸底线）
圆角：--ww-radius-sm 4px（badge/输入框） · --ww-radius-md 6px（按钮/菜单项） · --ww-radius-lg 8px（卡片/画布/弹层，上限）
阴影：优先 --dsw-shadow-lv1/2/3（宿主已有）；面板内卡片默认 border 分层 + 无阴影，仅弹层/下拉用 lv2+
动效：全盘宿主值 100/200/300ms + cubic-bezier(0.4,0,0.2,1)；禁 >400ms；prefers-reduced-motion 全局关
```

工程编辑风取向的落点：**线框分层（border-l1/l2）优先于阴影**；圆角上限 8px（卡片级），杜绝 ≥24px 过度圆滑。

### 6.5 布局常量

```
面板顶栏高 48px（Tab 条）· 列表行高 44px（触摸目标底线）
编辑器双栏分默认比例 1fr / 420px（预览画布固定 375 + 45 padding），拖拽调宽（resizable）
断点（面板内）：≥1200 双栏 · 900–1200 窄双栏 · <900 单栏 Tab 切换（编辑器三视图退化）
```

## 7. 图标方案

**锁定：lucide-react（唯一图标库，全项目不混用）。**

- 选型理由：① 约 1500 图标覆盖本项目全部域需求（calendar/clock/flame/image/layout-template/send/shield-check 等——官方 primitives 的 ~50 个 Icon\* 缺这些域图标）；② 描边风格（24 网格 2px stroke、圆角端点）与 DSH 官方 outline 图标视觉同族，混排不违和；③ tree-shakable ESM，只打包用到的图标，no-build 友好；④ ISC/MIT 许可。
- 落选说明：tabler-icons（约 5000 图标）数量占优但按需引入体验和 React 组件成熟度不如 lucide，且「多」不是本项目的选型维度——**克制才是**。
- 使用纪律：尺寸 16px（行内）/ 20px（按钮内）两档（面板级 UI 无 24px 独立图标场景）；颜色 = `currentColor`，不出现多色图标；语义映射表进 Phase 2 Spec（如：写作 pen-line / 排队 clock / 门禁 shield-check / 失败 shield-alert / 热榜 flame / 公众号 message-circle）。

## 8. 反 AI 模板味自查清单（13 项逐条对照）

| # | 反模式 | 本项目对照结论 |
|---|---|---|
| 1 | 紫→粉渐变三位一体（渐变+发光边框+毛玻璃） | 通过：token 层零 gradient 定义；无 glow 无 backdrop-filter（装饰性） |
| 2 | emoji 作功能图标 | 通过：唯一图标库 lucide-react；CI emoji 正则扫描；emoji 仅允许出现在文章正文 UGC |
| 3 | Lorem ipsum / "Welcome to" / 空洞占位 | 通过：§3–§4 所有空状态/按钮文案为真实中文产品文案，前端照抄不造句 |
| 4 | 千篇一律 Hero（大标题+CTA+3D 图形） | 通过：工具界面无营销 Hero；首屏 = 待办+最近文章（真实数据） |
| 5 | 默认靛蓝 #6366F1 强调 | 通过：accent = #4176E6（宿主 deepseek-500），非 Tailwind 默认蓝 |
| 6 | 圆角卡片 + 彩色左边框 | 通过：分组靠 border-l2 全边框 + hover 变色，无 border-left 强调手法 |
| 7 | 虚构指标（"10,000+ 用户信赖"） | 通过：数字全部来自真实回流（阅读 4,721 式有机值）或真实门禁分数 |
| 8 | 填充式文案（Seamless/Unleash/Elevate） | 通过：文案全是具体动作词：「推草稿箱」「AI 修这稿」「定位到段落」 |
| 9 | 硬编码颜色（组件内裸 hex） | 通过：全部经 --ww-* → --dsw-* 链；CI stylelint 禁裸 hex（白名单仅画布内排版主题） |
| 10 | 相同卡片网格无限重复 | 通过：文章库用数据表格而非三卡网格；写作台「最近文章」限 6 条且非等宽强调 |
| 11 | 幽灵卡片（1px 边框 + blur≥16px 阴影同存） | 通过：卡片 = 边框分层无阴影；阴影仅弹层 lv2+ |
| 12 | 过度圆角（卡片 ≥24px） | 通过：圆角上限 8px |
| 13 | 渐变文字 background-clip:text | 通过：无；文字强调只用字重/字号/颜色 |

补充自查（超出 13 项的工程纪律）：动效 ≤400ms 且 reduced-motion 支持（宿主动效值全盘沿用）；键盘可达（官方 primitives 自带 focus-visible，表格/编辑器是键盘主战场）；中文正文对比度 = `#0F1115` on `#FFFFFF` ≈ 17:1，次级 4.6:1+，全部达标。

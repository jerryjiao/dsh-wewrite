## 1. 问题陈述：Jerry 三痛点 → 结构化诊断

### 1.1 原话与转译

| Jerry 原话 | 转译为产品问题 | 诊断归属 |
|---|---|---|
| 「写作台看起来还挺难看的」 | 首屏是「仪表盘范式」而非「工作区范式」：三个松散区块垂直堆叠（今日待办 / 最近文章卡片 / 底部输入条），内容稀疏、视觉层级等权、无工作锚定感 | 信息架构（本文 §4）+ 视觉密度（设计师侧） |
| 「面板的排列不太好；页面空间感觉很小」 | 寄生面板宽 900–1400px 且被宿主 chrome 包围，当前每一页都是「整页平铺 + 独立大标题页头」，垂直方向被 48px Tab 条 + ~40px 页头吃掉约 90px；生成进度用全屏 Modal 遮断全部上下文 | 空间利用策略（本文 §3.2） |
| 「功能排布不清楚，分类也不清楚」 | 5 个平级 Tab 的分类逻辑映射的是「管线阶段」而非「用户心智」：写作台不写作（真编辑器藏在文章库下钻）、选题中心与写作台是两个平级的「开始一篇文章」入口、定时任务（低频管理）占了 1/5 导航权重 | 功能分类学（本文 §4） |

### 1.2 当前实现现状（源码核实，2026-08-19）

- 顶栏 `PanelTabBar`：5 个纯文字 Tab + 右侧公众号连接状态，高 48px（`src/client/components/PanelTabBar.tsx`）。
- 写作台 `TopicPanel`：今日待办 → 最近文章（≤6 卡片）→ 底部 sticky 主题输入条，单列垂直流。
- 选题中心 `HotspotsPanel`：左热榜列表 + 右关键词窄栏；「写这个」藏在行展开区内（两步操作）。
- 文章库 `ArticlesPanel`：全宽数据表格；编辑器是它的下钻路由（`/articles/:id`）。
- 定时任务 `SchedulePanel`：内部 queue/history 二级 Tab。
- 设置 `SettingsPanel`：左 5 组竖导航 + 右内容区。
- 生成中 `GenerationLayer`：全屏 Modal（`App.tsx`）。

### 2.2 跨竞品的三条共性规律

1. **创作工具没有「仪表盘首页」**：doocs/md、mdnice、秀米、135、微信后台，打开即编辑器（或作品列表→一键进编辑器）。没有任何一家把「待办+统计卡片」当首屏。首屏=工作内容本身。
2. **多文章管理走左侧窄栏**：doocs/md 的 PostSlider（把文章列表做成编辑器左栏，10–20% 宽、可折叠）、秀米「我的图文」、微信后台图文列表——「我在一篇文章里工作，旁边是我的其他文章」是写作工具的自然心智，胜过「库里浏览→点进去」。
3. **辅助功能全部右缘化/抽屉化/浮层化**：配置（doocs RightSlider）、素材（微信多媒体面板/135 样式库）、AI 指令（Canvas 选区菜单）都不占常驻主区；唯一例外是素材库类工具（135/秀米）把素材放左——因为素材是它们的生产品。我们不是素材工具，辅助功能应收在右缘或浮层。

## 3. 可迁移结论

### 3.1 适合寄生型插件面板的范式（宽度 900–1400px、被宿主 chrome 包围、不能全屏）

| 范式 | 来源 | 为什么适合我们 | 迁移方式 |
|---|---|---|---|
| **三视图模式 + 全可折叠面板**（edit / split / preview 一键切换，每栏可收） | doocs/md `viewMode` + ResizablePanel | doocs/md 的移动端/窄窗口形态就是我们的常态；它的空间哲学「空间永远让给当前任务」正是「空间感小」的解法 | 编辑器工作区支持仅编辑/双栏/仅预览三态 + 拖拽调宽；预览画布可缩放（L3） |
| **文章列表左栏化** | doocs/md PostSlider、秀米我的图文 | 把「文章库 Tab + 下钻编辑器」两层压成一层，改稿路径从 2 次点击变 1 次；左栏可折叠归零，窄面板下退化为顶部下拉 | 写作 Tab = 左栏文章列表 + 主区编辑器（L1） |
| **宿主界面不重复 + 单容器收拢 + 就地增强** | 壹伴 | 我们与壹伴同构（寄生在宿主 UI 内的增强插件）；壹伴证明了「功能长在使用场景处」比「功能目录」更清楚 | 设置不复制宿主已有能力（模型选择走宿主，现状保持）；生成指令出现在编辑器和写作启动视图处，不设独立「生成」页 |
| **AI 指令作用于选区/就地浮出** | ChatGPT Canvas、Notion AI | 我们的「AI 修这稿」「重写本段」就是选区指令；生成进度不应全屏遮断（Canvas 范式：AI 工作时用户仍能浏览） | 生成进度从全屏 Modal 改为可收起的侧边/角落卡片，跨 Tab 常驻顶栏进度点（L3） |
| **状态信息沉底** | doocs/md Footer、VS Code | 工程编辑风已定（DESIGN §3.4 StatusStrip 已有），扩展为全局模式 | 门禁分/字数/供应商等常驻状态条，不占内容区 |
| **极简双栏 + 主题控件进工具栏** | mdnice | 证明窄工具可以只有两栏：编辑+预览，主题选择是一级控件不占第三栏 | 编辑器顶部工具条含主题切换（现状保持并精简为一行） |

### 3.2 「窄空间做出大感觉」的六条具体策略（综合各竞品）

1. **垂直回收**：Tab 条 48→40px；砍掉每页独立大标题页头，标题与该页动作合并为一行工具条（省 ~40px/页）。
2. **一切辅助栏可折叠**：左栏（文章列表）、右抽屉（未来配置/样式）、预览画布，全部可一键收起；折叠状态本地持久化。
3. **三视图切换**：编辑/双栏/预览一键切，窄面板（<900px）自动退化为单栏 Tab（现状 narrow 逻辑保持）。
4. **生成不打断上下文**：进度组件小型化、可转后台（现有「转入后台」升级为默认形态），全屏 Modal 只保留首次提交后的短暂确认。
5. **密度分级**：管理型列表（文章库、历史）用紧凑行高（36px 档），创作型区域（编辑器、预览）保持舒展——「密的地方像工具，松的地方像纸面」。
6. **减少平级入口**：开始一篇文章的入口收敛为一处（写作台启动视图），热榜页只做「选题→带回主题」。

### 3.3 不适合的范式及原因

| 范式 | 来源 | 不适合的原因 |
|---|---|---|
| 自由布局画布 / 组件拖拽 / 图层系统 | 秀米（部分 135） | 重交互、宽空间需求（舒适区 ≥1300px）；我们的工作流是 Markdown 管线不是可视化拼装；与「克制工程风」审美冲突 |
| 大而全后台导航（多级侧边栏） | 微信公众平台后台 | 我们是单功能插件不是平台；多级导航在 900px 内挤占内容区 |
| 功能目录式侧边栏（几十个功能平铺分组） | 壹伴 60+ 功能收纳形态 | 我们功能面 ~10 个，目录化反而制造层级；壹伴是被功能数量逼的，我们没这个约束 |
| 常驻三栏以上（样式库+编辑+功能栏） | 135 | 三常驻栏舒适区 ≥1200px 且我们是 900–1400px 寄生面板；最多「一主一辅 + 可收抽屉」 |
| 独立 AI 对话页 | （反面参照）AIWriteX 类平台 | 我们的 AI 是管线执行者不是聊天对象；对话式 AI 页与「管线可复现」定位冲突（v0.1 PRD 已排除，此处仅记录布局结论） |

## 4. 功能分类学重排提案

### 4.1 当前 5 Tab 的归类问题诊断

| 问题 | 证据（当前实现） | 结论 |
|---|---|---|
| 「写作台」名不副实 | TopicPanel 不含任何写作面：它是待办列表 + 卡片 + 输入条；真正写作在文章库下钻两跳之外的编辑器 | 仪表盘范式错配——创作工具首屏应是工作区（§2.2 规律 1） |
| 「开始一篇文章」有两个平级入口 | 写作台底部输入条 vs 选题中心「写这个」，分居两个 Tab | 入口应收敛：热榜负责「给主题」，写作台负责「开工」，跳转关系应为「选题中心 → 写作台」单向流 |
| 「文章库」与「编辑器」是人为两层 | Articles 全宽表格 → 点行 → EditorPanel 下钻 | 应合并为一层：列表是工作区的左栏（PostSlider 范式），编辑器是默认态 |
| 「定时任务」占用 1/5 顶级导航 | SchedulePanel 是低频管理页（配好后少动；创建入口本就在编辑器「推草稿箱 ▾ → 定时」） | 导航权重与使用频率不匹配——应降权（图标化/右移），但因含队列+历史两类实体，保留独立页不塞抽屉 |
| 顶栏与页头双重标题 | PanelTabBar「文章库」+ 页内 `<h2>文章库（28）` 每页重复 | 垂直空间浪费，二者合并为一层 |
| 状态类功能散落 | 连接状态在顶栏右（合理）；生成进度在全屏 Modal（遮挡）；门禁状态在列表列+编辑器 Tab（合理） | 生成进度应常驻化、可转后台（Canvas 范式） |

### 4.2 新信息架构：5 Tab → 4 Tab（写作工作区范式）

```
顶栏（40px）：[写作] [选题] [定时] ····· 生成进度点(运行中) · 公众号连接状态 · [设置图标]

写作（Workbench，默认 Tab）＝ 原「写作台 + 文章库 + 编辑器」三页合并
├── 左栏（240–280px，可折叠，折叠态退化为窄图标条或顶部下拉）
│   ├── 搜索 + 状态筛选（全部/草稿/门禁未过/已进草稿箱）
│   ├── 文章紧凑列表（36px 行：标题 + 状态点 + 门禁标记）
│   └── 底部 [新文章] 主按钮 → 展开「输入主题 / 从热榜挑」两路入口
├── 主区 ＝ 编辑器（默认载入最近编辑的一篇）
│   ├── 精简页头一行：返回列表(仅窄栏折叠时) · 标题 · 状态 · 自动保存 · [仅编辑|双栏|仅预览] 三视图 · [推草稿箱 ▾]
│   ├── 双栏：CodeMirror + 375px 预览画布（可拖拽调宽）
│   └── StatusStrip 状态条（现状保留）
└── 空态（无任何文章/新装）：中央主题输入大卡 + [去选题中心] + [配置公众号]——启动视图即工作区

选题（Hotspots）＝ 现状保留 + 动作前置（「写这个」hover 可见不必展开）
定时（Schedule）＝ 现状保留，Tab 图标化降权
设置（Settings）＝ 现状保留（左 5 组导航），从文字 Tab 改为顶栏右端齿轮图标
```

**为什么是 4 个而不是 3 个或维持 5 个**：
- 定时任务含「队列 + 历史」两个实体列表，塞进抽屉空间不够（历史需要表格宽度）；并进设置则混淆「配置」与「运营」语义。保留为 Tab 但图标化，导航权重与频率对齐。
- 文章库降为左栏后顶级对象从 5 个减到 4 个（写作/选题/定时/设置），认知负荷下降且每个 Tab 语义单一：「写作=产出内容的地方，选题=找题的地方，定时=排期的地方，设置=配参数的地方」。
- 保留方案 B（不动 Tab 结构只重做写作台视觉）作为降级路径，见 §5 说明。

### 4.3 迁移与兼容

- 路由变化：`/`（写作工作区，含列表态与编辑态）+ `/hotspots` + `/schedule` + `/settings`；`/articles`、`/articles/:id` 保留为重定向（老书签/外部链接不断）。
- 功能零删减：本提案只移动功能位置，不删除任何 v0.1.4 已有能力。
- 「今日待办」内容不丢失：待办语义由左栏状态徽标（门禁未过红点、定时即将执行标记）+ 顶栏生成进度点承接，不再需要独立待办区块。

## 5. 重设计 PRD 增量（RICE 排序）

RICE 口径沿用 v0.1 PRD：R=受影响用户占比(1–10)，I=单用户影响(0.25/0.5/1/2/3)，C=确信度，E=人月(1=半天…10=3 个月+)。Score = R×I×C/E。
本清单为 v0.2 布局迭代增量，Jerry 三痛点全覆盖；智谱免费模型接入与 Playwright 全用例测试不在本清单（架构师负责）。

| ID | 改进项 | R | I | C | E | Score | 承接痛点 |
|---|---|---|---|---|---|---|---|
| L2 | 顶栏信息架构重排（Tab 5→4 + 页头合并） | 10 | 2 | 80% | 2 | **8.0** | 排列 / 空间 / 分类 |
| L1 | 写作工作区化（文章库左栏 + 编辑器默认态） | 10 | 3 | 80% | 4 | **6.0** | 难看 / 空间 / 分类 |
| L5 | 选题中心动作前置（「写这个」免展开） | 7 | 1 | 80% | 1 | **5.6** | 排列 |
| L7 | 写作台视觉密度与层级规范（设计师协同项） | 10 | 2 | 50% | 2 | 5.0 | 难看 |
| L4 | 新用户/无文章启动视图（空态即工作区） | 6 | 2 | 80% | 2 | **4.8** | 难看 / 分类 |
| L3 | 空间利用专项（三视图 + 生成进度去全屏化 + 密度分级） | 8 | 2 | 80% | 3 | **4.3** | 空间 |
| L6 | 定时任务页动作摘要行 | 5 | 0.5 | 80% | 1 | 2.0 | 分类 |

**实施顺序说明**：L1+L2 是同一刀的两面（结构重排），合为第一个交付批次；L5/L4/L3 为第二批次（各自独立可发）；L6 最低优。L7 的视觉规范由设计师颜好看基于本 PRD 的密度/层级要求出 Design 增量，PM 只定验收不动视觉细节。

### L2 顶栏信息架构重排（Score 8.0，P0）

- **用户问题**：5 个平级文字 Tab 分类是管线视角不是用户视角；每页顶部「Tab 条 + 大标题页头」双重复读，垂直空间浪费；「设置」作为低频页占 1/5 导航宽度。
- **改什么**：Tab 收敛为 4（写作/选题/定时），设置改为顶栏右端齿轮图标入口；各页页内 `<h2>` 大标题与该页动作条合并为一行 40px 工具条（标题+筛选+主动作同排）；顶栏高 48→40px；生成运行中在顶栏显示可点击的进度点（替代部分全屏 Modal 场景）。
- **验收标准（Given/When/Then）**：
  - Given 用户打开面板， Then 顶栏可见且仅可见 4 个导航对象（3 Tab + 设置图标），顶栏总高 ≤40px。
  - Given 任一页面加载，Then 页面顶部不存在独立大标题行，标题与该页操作在同一工具条行内。
  - Given 管线运行中，Then 顶栏出现进度点入口，点击可展开进度视图，不遮挡当前页其余区域。
  - Given 用户此前折叠过文章左栏，Then 重启面板后折叠状态保持（本地持久化）。

### L1 写作工作区化（Score 6.0，P0，本提案核心）

- **用户问题**：写作台不写作——打开插件看到的是稀疏仪表盘（待办/卡片/输入条），真正改稿要「文章库 Tab → 点行 → 编辑器」两跳；「空间小、难看、分类乱」三症同源。
- **改什么**：Tab 1 重构为工作区：左栏文章紧凑列表（搜索/状态筛选/门禁标记，可折叠），主区编辑器默认载入最近编辑的一篇；「新文章」入口（主题输入 + 从热榜挑）移至左栏底部主按钮；原「今日待办」语义由左栏徽标 + 顶栏进度点承接；空文章时主区显示启动视图（见 L4）。布局参照 doocs/md PostSlider + 中央编辑组。
- **验收标准**：
  - Given 存在历史文章，When 用户打开面板，Then 默认 Tab 为写作工作区且编辑器已载入最近编辑的一篇（含其预览与门禁状态）。
  - Given 用户想改另一篇，When 点击左栏任一条目，Then 编辑器切换 ≤1 次点击完成，无整页跳转。
  - Given 面板宽 <900px，Then 左栏自动折叠为顶部文章下拉选择器，编辑器单栏。
  - Given 某篇文章门禁未过，Then 左栏该行显示红色门禁标记，点击进入编辑器门禁视图。
  - Given 用户点击左栏底部「新文章」，Then 展开主题输入与「从热榜挑」两个入口，Enter 提交即启动管线并显示进度（不整页跳走）。

### L5 选题中心动作前置（Score 5.6，P1）

- **用户问题**：看到一条想写的热榜，需要「点行展开 → 点写这个」两步，展开态还会撑高列表。
- **改什么**：热榜行 hover 时右侧显示「写这个」ghost 按钮（键盘可达：焦点行 Enter 即写）；展开区保留原文链接、AI 分析等次级内容；「收藏」按钮 v0.1.4 尚无实际行为，改为「复制链接」或在 v0.2 实装收藏前隐藏（不做无行为的按钮）。
- **验收标准**：
  - Given 热榜已加载，When 用户 hover/键盘聚焦任一未展开行，Then 「写这个」按钮可见，单击即以该条目为题启动管线。
  - Given 用户点击行主体（非按钮），Then 行为仍是展开/收起次级信息（不触发写作）。
  - Given 无绑定行为的按钮，Then 界面不出现（收藏按钮在实装前隐藏）。

### L7 写作区视觉密度与层级规范（Score 5.0，P1，设计师协同）

- **用户问题**：「写作台难看」的视觉半边：当前三区块等权堆叠、卡片留白不一致、无「工作锚定感」。本项是 L1 的视觉面配套。
- **改什么**：由设计师基于 L1 新结构出增量规范：列表行高两档（管理 36px/交互 44px）、区块标题降级为 13px 次级标签、卡片改线框分层（禁阴影堆叠）、每屏 accent ≤2 处的规则在新结构下重新分配（左栏选中态 + 主 CTA）。约束：延续既有 `--ww-*` token 体系与 lucide-react 单图标库，不引入新视觉语言。
- **验收标准**：
  - Given L1 完成，Then 设计增量覆盖左栏/工具条/编辑器三处的密度与层级规格，且通过 P0 视觉门禁三条自查。
  - Given 走查新首屏，Then 无两个视觉权重相同的区块并存（存在明确的单一焦点=编辑器）。

### L4 启动视图（空态即工作区）（Score 4.8，P1）

- **用户问题**：新用户/零文章时首屏是三个空态区块，「难看」且不知从哪开始。
- **改什么**：无文章时工作区主区显示单一启动卡：中央主题输入（大输入框 + 「开始写作」主按钮）+ 两个次级入口（「去选题中心挑热榜」/「先配置公众号凭据」，按配置状态智能显示其一为次按钮）；配好后第一次出稿，启动卡自动退位给编辑器。
- **验收标准**：
  - Given 全新安装且未配置凭据，When 打开写作 Tab，Then 主区仅呈现一个启动卡，路径选择 ≤2 个（开始写作 / 去配置）。
  - Given 输入主题并 Enter，Then 管线启动且启动卡转为进度视图（就地，不跳页）。
  - Given 已有至少一篇文章，Then 启动卡不再默认出现（新文章入口在左栏底部按钮内）。

### L3 空间利用专项（Score 4.3，P1）

- **用户问题**：「页面空间感觉很小」——全屏生成 Modal 遮断一切；编辑器只有 edit/preview/gate 三 Tab 切换没有「仅编辑/双栏/仅预览」的空间弹性；预览画布不可缩放。
- **改什么**：① 生成进度默认为右下角可展开卡片（顶栏进度点为常驻入口），全屏 Modal 仅保留首次提交确认，用户可随时收起继续浏览任意 Tab；② 编辑器视图模式改为「仅编辑 / 双栏 / 仅预览」三态 + 分栏可拖拽（门禁报告改为双栏下的第三 Tab 或右侧覆盖面板，不再与视图模式混排）；③ 预览画布支持 100%/90%/75% 缩放档位。
- **验收标准**：
  - Given 管线运行中，When 用户切换到选题 Tab，Then 进度不遮挡页面，顶栏进度点仍可见可点，展开可回看进度详情。
  - Given 编辑器双栏态，When 拖动分栏线，Then 两栏宽度实时调整且预览不整页重排闪烁；窄面板下自动退单栏。
  - Given 用户选择「仅编辑」态，Then 预览栏完全收起，编辑区占满内容区。
  - Given 预览缩放切到 90%，Then 画布等比缩小且渲染内容与推草稿箱载荷仍字节一致（缩放是视觉变换不是二次渲染）。

### L6 定时任务页动作摘要行（Score 2.0，P2）

- **用户问题**：进定时页先看到队列列表，但用户最常问的是「下一次是什么时候、跑什么」。
- **改什么**：页顶加一行摘要：下一次执行时间 + 名称 + 目标（草稿箱），右侧「新建定时」；队列/历史二级 Tab 保持。
- **验收标准**：Given 存在启用的排期，When 打开定时 Tab，Then 无需滚动即可看到下一次执行的时间与对象。

## 6. 边界与非功能（本迭代增量口径）

| 项 | 要求 |
|---|---|
| 不翻案 | 产品定位、安全默认（草稿箱默认/群发人工/凭据本地/日志脱敏）、v0.1 功能集全部保持；本 PRD 仅移动功能位置与重排空间 |
| P0 视觉门禁 | 三条全量适用；新结构中所有图标走 lucide-react 单库；无新增渐变/emoji/占位文案 |
| 兼容 | `/articles`、`/articles/:id` 旧路由重定向到工作区对应态；已有用户 localStorage（关键词等）不受影响 |
| 性能 | 工作区首屏 = 编辑器 + 列表同屏，本地渲染 <1s 预览刷新口径不变；左栏列表虚拟滚动阈值沿用 MAX_VISIBLE=200 |
| 降级方案 | 若 L1 结构改造延期，可先发 L2+L5+L4（顶栏重排 + 动作前置 + 启动视图）作为 v0.2 最小布局包，L1/L3 顺延 v0.3——但需总监明确拍板，因 L2 的 Tab 语义（文章库并入写作）依赖 L1，若 L1 延期则 L2 需改为保留 5 Tab 的纯收窄版 |
| 不在本 PRD | 智谱免费模型接入、Playwright 全用例测试（架构师负责）；主题模板库/样式市场（Backlog，若做则参照 135/秀米左栏素材库范式） |

## 0. 问题定义（为什么「素」）

Jerry 的判断经截图逐视图核实，完全成立。现状色彩盘点：

| 层 | 现状 | 问题 |
|---|---|---|
| 基底 | light：面板 #FFFFFF + 工作台底 #F9FAFB（宿主 specific-sidebar-fill，**无彩灰**）+ 卡 #FFFFFF | 台面与纸面全是白/近白灰，**零色相**——「白纸感」的根源不是白卡，是台面无色温 |
| 品牌 | accent #4176E6 仅出现在 CTA/激活 Tab/链接（每屏 1-2 处，纪律正确） | 单点蓝色撑不起「主题」——蓝是墨水，不是台面 |
| 语义 | success 绿 / warn 琥珀 / danger 红，仅在状态出现时 | 正确且克制，但常态页面看不见 |
| 数据 | 热榜 rank 灰 mono、门禁分数绿/红、进度阶段绿/蓝/红 | 数据层无品牌色温，榜单 30 行是一片灰字 |
| 缺失 | 无第二层色彩：无视图识别色、无数据可视化档、边框/分隔线全中性黑 | v0.2-v0.3 的「线框分层语言」全是灰线，专业但素 |

**根因一句话**：v0.2 引入的「灰台白卡」双层表面解决的是空间感，但它借用的宿主 token（sidebar-fill #F9FAFB）是**无色相的功能灰**——整个插件没有属于自己的「台面色温」，也就没有主题记忆点。

## 1. 方向裁决（参照系与落点）

### 1-1 参照系光谱

| 参照 | 用色策略 | 与本项目关系 |
|---|---|---|
| Notion / iA Writer | 近零色相，主题感来自内容与排版 | **正是现状**，已被 Jerry 否决 |
| Craft / Apple iWork | 每模块/每文档一个识别色，微面积点缀 | 「视图识别色」的先例——专业工具用色相区分模块 |
| **Linear（light）** | 冷调蓝灰底 + 单品牌紫平涂，浅色下台面带明确色温 | 台面 tint 的直接参照（我们换成品牌蓝） |
| **Stripe Dashboard** | 品牌浸染：tint 背景 + 彩色数据可视化 + 每页识别图形 | Jerry 历史实证参照（纯色平涂、蓝系安全）；数据层与浸染度的参照 |

**落点：Linear light 的冷调台面 + Stripe Dashboard 的品牌浸染深度，两者之间。**

三条论据：

1. **寄生插件需要「域」的边界**。插件面板嵌在 DSH 宿主中心栏，宿主会话栏/内容区是无彩灰。台面带品牌 hue 后，「进入写作台」产生一次可感知的色温切换（#F9FAFB 灰 → #F2F4F8 蓝灰），这是不花一像素装饰就能拿到的主题感——也是 Linear/Slack 嵌入面板的通行做法。
2. **Jerry 口味实证**：纯色平涂不要渐变（Stripe 参照）、浅色底深色内容、蓝色系安全、logo 纯色 #4176E6。tint 方案全部命中：纯色平涂的浅蓝灰底，无任何 gradient。
3. **写作语义自洽：「台面染，纸面不染」**。专业写作台的物理隐喻——桌面是深色的/有质感的，纸是白的。编辑器 CodeMirror 表面、微信预览画布、输入框内部全部保持白（dark 下保持宿主灰），tint 只落在工作台底/rail/槽/边框/骨架这些「台面家具」上。写作台 = 品牌蓝灰台面 + 白纸 + 一支品牌蓝的笔。

### 1-2 主题代号：Bluewash（蓝染）

全称「Bluewash 蓝染工作台」。三层色彩架构：

| 层 | 名称 | 面积 | 内容 |
|---|---|---|---|
| L1 | **基底浸染层** | 最大（台面 100%） | bg-page / surface-sunken / canvas-well / border×3 / divider / skeleton 从无彩灰 → 品牌冷调蓝灰（hue 219，与 #4176E6 同族），饱和度压在 20-33%——可感知的色温，不可感知的「彩色」 |
| L2 | **品牌操作层** | 中（每屏 ≤2 处） | accent #4176E6 家族不动（CTA/选中/链接/focus）；accent-subtle 修复为深浅双态（light #EDF3FE 不变 / dark 新增 #1E2B4D），顺手解除 v0.3 反复绕开的深色选中底风险 |
| L3 | **域识别与数据层** | 微（点/字/icon 级） | 三域识别色（写作=品牌蓝 / 选题=热力橙 / 定时=青）+ 热榜 Top3 名次橙 + 空态/启动卡品牌 glyph + 侧边栏入口品牌蓝 icon |

关键克制：**L3 永远不染大面积底**——识别色只出现在导航激活态、页头 8px 圆点、名次数字、单枚 icon 上。色相预算纪律：同屏非中性色相 ≤2 种（操作蓝 + 当前域识别色；热榜页 = 蓝 + 橙，恰为双色节奏：蓝=命中、橙=热度）。

### 1-3 域识别色选色（预裁决的「每视图识别色」采纳 + 收敛）

总监预裁决方向采纳，但做三点收敛：

1. **只给三个「域」设识别色，设置页不设**（Apple 先例：设置永远中性灰）。文章库在 rail 内属写作域，不单设。
2. **色相避开语义色领地**：
   - 选题（flame 热榜）= 热力橙 **#C2410C**（orange-700 深档；与 warn #F59E0B 琥珀保持色距，且识别色只染导航/页头/名次，warn 只在状态点/警示条，视觉路径不重叠）
   - 定时（calendar-clock）= 青 **#0F766E**（teal-700；与 success #22C55E 绿分得开，场景也不重叠）
   - 写作（pen-line）= **--ww-accent 家族**（不另设 token，避免同值重复；品牌蓝即写作域色）
3. **dark 提亮版同步定**：橙 #FB923C / 青 #2DD4BF（对比度核算见 design 篇 §5）。

热榜 Top3 名次数字用 --ww-rank-top（= 选题橙同值独立槽）：热榜的「热度」语义与选题域同源，榜单页形成「蓝（命中行）/橙（Top3 名次）」的信息编码双色，不再需要第三种颜色。

### 1-4 架构代价声明（宿主引用 → 自有色板的部分让渡）

现状 6 个表面/边框 token 走宿主 --dsw-* 自动翻转，dark 覆写块仅 4 条。本方案后 bg-page / surface-sunken / accent-subtle / canvas-well / border / border-strong / divider / skeleton 转为自有值（宿主没有「品牌蓝灰 tint」这个槽，主题色是我们自己的设计资产），dark 覆写块增至 15 条。**换来的是主题控制权**；宿主换肤时这 8 个 token 不再跟随（其余 20+ 个颜色 token 仍全走宿主）。这个让渡是「要有主题」的必要成本，且被收敛在明确的 8+3 个 token 内。

## 2. 方案总纲（每视图一眼变化）

| 视图 | 变化（详情与 CSS 落点见 design 篇 §4） |
|---|---|
| 全部（台面） | 工作台底/rail/顶栏融合底从灰 → 品牌蓝灰；全部边框/分隔线带蓝灰笔触；骨架屏品牌灰 |
| 写作台 | 启动卡 glyph 圆从灰 → 浅蓝底 + 蓝 icon（首屏品牌时刻）；rail 选中行浅蓝底在深色下首次成立 |
| 选题中心（热榜） | 激活 Tab「选题」= 热力橙；页头 8px 橙点；**Top3 名次数字橙色**（4+ 保持灰）；命中行浅蓝底不变——双色数据节奏 |
| 定时 | 激活 Tab「定时」= 青；页头青点；暂停卡随台面 tint |
| 编辑器 | 台面（状态栏/页头线）tint；**纸面（编辑区/画布/输入框）保持白**；选区浅蓝在深色下首次成立 |
| 设置 | 无识别色（中性）；激活 nav 浅蓝底在深色下首次成立 |
| 浮层/侧边入口 | 浮层头白条浮蓝灰台；**侧边栏「写作台」入口 icon 染品牌蓝**（宿主灰 sidebar 里的品牌锚点） |
| 深色主题 | 全部同步设计：台面蓝黑 #1A1E26 / 槽 #20242E / 边框微蓝 / 选中底 #1E2B4D——Linear dark 式色温，非事后补 |

## 3. 硬约束对账（P0 门禁 + 项目既定纪律）

| 约束 | 本方案遵守方式 |
|---|---|
| 零 gradient（stylelint 全禁） | tint 全部纯色平涂；本文与 design 篇零 gradient 定义 |
| 禁紫粉四色 / emoji 图标 / AI 模板味 | 零出现；无新增图标（dot 是 CSS 圆，不是图标） |
| 组件只引 --ww-*，禁裸 hex | 全部新色进 token（3 新增 + 11 修改），组件层零裸值 |
| 深浅双主题成立 | 8 个转自有的 token 全部给 dark 覆写值；3 个新增 token 双态定值 |
| DOM 契约冻结 | 零改名零改结构；DOM 增量仅 3 处**新增**属性/元素（tab data-view / pagebar dot / rank 修饰类），属「可加新类」许可范围 |
| localStorage 键 / 图标库 / Motion=3 | 零变化（无新动效，无新图标名） |
| Jerry 口味（纯色平涂/浅底深内容/蓝系安全） | §1-1 论据 2 逐条命中 |

## 4. 非目标

- 不改布局/间距/字号/动效（v0.2-v0.3 已定稿，本方案纯色彩维度）。
- 不动宿主 chrome（会话栏/tab 环/宿主 sidebar 底色）——作用域仍限 .dsh-wewrite-panel + .ww-sidebar-entry + .ww-overlay。
- 不动微信预览画布内的 UGC 排版主题（画布白底契约不变）。
- 不做用户可切换的多主题（单一 Bluewash 主题，跟随宿主深浅二态）。
- 语义色（success/warn/danger/info）不动——状态语义与品牌主题分离。

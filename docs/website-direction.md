## 1. 官网定位一句话 + 信息架构

### 1.1 定位一句话

**开源产品的信任前置页——不是营销页，是 README 的门厅与安装入口：三分钟内让一个 DSH 用户看清「这是什么、凭什么信、怎么装」，然后去 GitHub。**

推论：官网不承载转化漏斗（无注册、无付费），唯一转化动作 = 复制安装命令 / 跳 GitHub。所有设计决策围绕「少说一句废话，多给一个可核查的事实」。

### 1.2 信息架构（8 章节，单页锚点导航）

| # | 章节 | 锚点 ID | 一句话职责 | 内容真源 |
|---|------|---------|-----------|---------|
| 0 | 导航 | — | 锚点 ×5 + GitHub 按钮，非 sticky | — |
| 1 | Hero | `top` | logo 位 + wordmark + slogan + 安装命令复制块 + GitHub 按钮 + 真实 meta 行 | README 首段 |
| 2 | 它解决什么 | `problem` | 三段痛点（PRD §1 四条并为三段，合并理由见 §5.2） | PRD §1 |
| 3 | 5 分钟上手 | `quickstart` | 装 → 配 → 出一篇，竖排三步 | README「5 分钟快速开始」 |
| 4 | 它做什么 | `features` | 六项功能，管线全宽块 + 5 小项分数网格 | README「功能亮点」 |
| 5 | 安全默认 | `safety` | 四条价值观（草稿箱锁定 / 凭据本地 / 日志脱敏 / 无遥测） | README「安全声明」 |
| 6 | 架构 | `architecture` | ASCII 架构图（与 README 同图） | README「架构」 |
| 7 | FAQ | `faq` | 精选 3 条（errcode 40164 必入） | README FAQ |
| 8 | Footer | — | repo / docs / issues / license + 版权 + 价值观短句行 | — |

### 1.3 对任务给定结构的两处优化（含理由）

1. **「六大功能」改为 1 全宽 + 5 小项的分数网格，不做 6 等卡**。理由：六个等尺寸图标卡是 AI 模板味第 5 反模式的典型形态；且六项中「管线」是差异化主证（含六步流程可视化），应占全宽主位，其余 5 项是平级特性，用 3+2 分数网格（末行 2 项更宽）制造有意的非均质。
2. **「5 分钟上手」三步用竖排三行而非横向三卡**。理由：①第 1 步内嵌安装命令块，内容高度天然不等，横排三卡会被迫拉齐（假均质）；②竖排在桌面与移动端同构，单断点 900px 下无需变换布局，少一套响应式规则。

其余章节顺序保持任务给定不动：「问题 → 方案 → 怎么用 → 细节 → 信任 → 问答」是单页开源产品页的诚实叙事序，安全默认放在架构前（价值观先于实现细节，PRD §3.3 第 3 条定位其为差异化卖点）。

## 3. 章节布局说明（逐节）

### 3.0 导航

- 高 56px，白底，底 1px `--site-divider`。**非 sticky**：单页 8 章节、页长可控，sticky 带来的常驻遮挡收益低于其复杂度；滚动回顶靠 wordmark 链接（`#top`）。
- 左：wordmark 纯文字链（mono，见 §6.2）。右：5 个锚点链接（14px）+ GitHub 按钮（outline 样式，star 图标）。5 项锚点满足认知负荷 ≤5。
- <900px：锚点行隐藏，仅剩 wordmark + GitHub 按钮——**不做移动菜单**（理由与备选方案见 §7.2）。

### 3.1 Hero

- 桌面双栏 `grid-template-columns: minmax(0,7fr) minmax(0,5fr)`，gap 48px；上下留白 80px。
- 左栏：mark 40px + wordmark（产品名 mono 呈现，§6.2）→ H1 两行（40px/700/-0.01em，第二行 accent 纯色文字——Hero 唯一 accent 使用，见 §4.3 限额）→ 副文两行（16px，`--site-fg-secondary`，行高 1.7）→ CTA 行（主按钮「GitHub 仓库」+ 次按钮「5 分钟上手」锚点带 arrow-down 图标）。
- 右栏安装块：sunken 底 + 1px 边框 + radius 8px。顶栏（sunken 加深行）左「bash」等宽标签、右复制按钮（copy 图标 → 点击变 check + 「已复制」aria-live，1.5s 复位）。命令体等宽 13px/1.6，`$` 提示符与命令分色（提示符用 fg-secondary）。尾行 `→ http://127.0.0.1:3080` 表示产物地址。块下前提行 12px：Node 与 DSH 版本要求。
- Hero 下沿 meta 行：等宽 12px，四项真实可核查事实以 ` · ` 分隔，flex-wrap。
- **Hero 的主视觉就是真实的安装命令，不是抽象图形或产品截图拼贴**——安装块右置而非居中，构成非对称双栏，规避「大标题+居中 CTA」模板 Hero。

### 3.2 S1 它解决什么

- sunken 底（`--site-bg-sunken`），节上下留白 80px。
- 标题 24px/700 左对齐 + 引句 16px（fg-secondary）。
- 三列 grid（`repeat(3, 1fr)`，gap 48px），列间以 1px `--site-divider` 拆分（`border-left` 用中性 divider 色非彩色，合规——禁的是 >1px **彩色**侧边条）。每列：图标 20px（fg-secondary 色，克制）→ 小标题 18px/500 → 段落 14px/1.7。
- 无卡片盒（透明底），与 S3 的实体块形成密度对比。
- 末尾转折句：整行段落，句首等宽「→」，把痛点接到产品。

### 3.3 S2 5 分钟上手

- 白底。竖排三行，行高以内容为准，行间 1px divider + 24px 上下 padding。
- 每行两栏：左 = 步骤号（mono，32px/700，fg-secondary，宽 72px 固定）；右 = 标题 18px/500 + 正文 14px；第 1 步正文下内嵌单行命令块（code-bg 底 + 等宽 13px + 复制按钮，样式继承 Hero 安装块的行内缩小版）。
- 步骤号是流程性编号（配 divider 时间线语义），非「01 · 关于」式装饰编号。

### 3.4 S3 它做什么

- sunken 底。管线块：白 surface 底 + 1px border + radius 8px + padding 24px，块内含「图标 + 标题 + 说明」与**六步流程条**（等宽 13px，步骤间「→」，过门禁一 步「门禁」二字下加 `--site-success` 色下划线提示拦截语义——语义色是信息不是装饰，不计 accent 限额）。
- 5 小项：6 列分数网格 `repeat(6,1fr)`，第 1 行三项各 span 2，第 2 行两项各 span 3；行间距 24px。小项无盒：顶部 1px fg 色 2px？——修正：小项顶部 1px `--site-border` 线 + padding-top 16px，图标 20px + 标题 16px/500 + 说明 14px。**不做第六张凑数卡**，5 项就是 5 项。

### 3.5 S4 安全默认

- 白底。标题 + 引句后，四列 grid（`repeat(4,1fr)`，gap 48px）。
- 每列：图标 20px（fg 色）→ 粗标题 16px/500 → 说明 14px。列顶 1px fg 线（`--site-border-strong`），无盒、无底色——四条价值观用「编表」而非「堆卡」呈现，形态与 S1 的三列痛点形成呼应但零图标彩度差异（S1 图标灰、S4 图标深）。

### 3.6 S5 架构

- sunken 底。ASCII 图置于 pre 块：`--site-code-bg` 底 + 1px border + radius 8px + padding 24px，等宽 13px/1.5，`overflow-x: auto`。
- 图内容**与 README「架构」节同图**（见 §9.5 同步义务）。图下一行文字链指向 docs/tech-architecture.md。

### 3.7 S6 FAQ

- 白底。3 个原生 `details/summary`，summary 行：16px/500 + chevron-down 图标（`details[open]` 时 CSS 旋转 180deg，零 JS）。条目间 1px divider。
- 答案体 14px/1.7；40164 答案中「两条出路」用有序列表，代理方案附 tools/wechat-relay 文档链接。

### 3.8 Footer

- sunken 底，顶 1px divider，上下留白 48px。
- 桌面两栏：左品牌块（mark 24px + wordmark + 一句话 + 版权行），右链接列（GitHub 仓库 / 文档 / Issues / MIT License，各配 external-link 或对应图标 16px，14px 文字）。
- 底行：等宽 12px 价值观短句，与 Hero meta 行首尾呼应。

## 9. 前端实现提示

### 9.1 技术栈与结构

- **Astro 静态单页**（workspace 静态站默认栈）：`website/` 目录（repo 根下），单 `index.astro` + `global.css`（含 `--site-*` tokens，命名与本文档一一对应）+ 内联 `<script>`。零框架运行时、零外部 JS 依赖。
- `astro.config.mjs`：`site: 'https://jerryjiao.github.io'`，`base: '/dsh-wewrite/'`（GitHub Pages 项目页子路径；若绑自定义域名则去 base）。
- 发布：`.github/workflows/website.yml` —— `withastro/action` 构建 + `actions/deploy-pages`，main 分支推送即发布。

### 9.2 JS 预算与交互（<3KB 内联脚本）

1. **复制按钮**（唯一必需 JS）：`navigator.clipboard.writeText` + `document.execCommand('copy')` 降级；成功后 copy→check 图标切换 + `aria-live="polite"` 文字「已复制」，1.5s 复位；键盘可达（button 元素原生）。
2. 移动菜单：按 §7.2 主案**不实现**；备选 details/summary 方案同样零 JS。
3. 除此之外零 JS：FAQ 用原生 details；导航锚点原生；无统计、无字体 CDN 请求、无 cookie。

### 9.3 资产

- `assets/logo/mark-1024.png` —— 唯一设计位图（favicon 32/180/512 与 og:image 1200×630 在构建时用 sharp 从它派生，或手动提交派生件）。
- og:image 构成：白底、wordmark + slogan 单行（mono/黑）、底部 #4176E6 纯色条——平涂，无渐变。
- `assets/fonts/JetBrainsMono-{400,500}.woff2` —— latin 子集自托管，`@font-face` + `font-display: swap`。

### 9.4 CI 门禁（构造保证固化）

website 构建工作流内加四步扫描（与主仓 `check:p0` 同构，对象 = website/src 与 dist）：

```bash
rg '[\x{1F300}-\x{1F9FF}\x{2600}-\x{26FF}\x{2700}-\x{27BF}]' website/src website/dist   # emoji：零命中
rg 'linear-gradient' website/src website/dist                                          # 渐变：零命中
rg -in '#7C3AED|#A855F7|#EC4899|#6366F1' website/src website/dist                      # 紫粉四色：零命中
rg -in 'lorem|ipsum|welcome to|sign up today|get started|欢迎使用|敬请期待|coming soon' website/src website/dist  # 占位词：零命中
```

### 9.5 同步义务与已知坑

- **架构图双源同步**：S5 与 README「架构」为同图两处。改架构必须同步两处——在 website/ 内加注释指针（`<!-- sync: README.md 架构节 -->`）提醒，或在构建时从 README 提取该代码块（若实施方觉得值得，不做强制）。
- 版本 pin：安装命令中的 `#v0.1.0` 与 Hero meta 行随发版手动更新（发版 checklist 加一条）。
- 无障碍底线：对比度全部过 AA（fg 17:1 / fg-secondary 4.9:1）；`details/summary` 原生键盘可达；`prefers-reduced-motion` 全局关闭块照搬 DESIGN.md；纯图标按钮（复制）带 aria-label。
